Brief analysis of the application
This application counts only vehicles moving from downtown to city centre by combining motion segmentation, spatial filtering, and simple multi-object tracking. The practical workflow is: (1) isolate motion candidates, (2) keep only blobs inside a main-street region of interest (ROI), (3) track each vehicle with a persistent ID using centroid matching, and (4) increment the counter once when a tracked centroid crosses the counting line in the correct direction. This direction rule is essential because traffic appears from multiple directions in the scene. Without directional logic, the same system would count irrelevant movement or mixed traffic flows.

The generated results show that Traffic_Laramie_1.mp4 contains a larger downtown-to-city-centre flow than Traffic_Laramie_2.mp4 within the observed intervals. The per-minute normalization is useful because it compares traffic intensity fairly even when video durations differ. In practical deployment, this rate-based metric is more informative than raw totals alone because it supports direct peak-hour comparisons across multiple recordings.

Frame differencing and background subtraction
Frame differencing computes motion as a pixel-wise absolute difference between consecutive frames:

D_t(x,y) = |I_t(x,y) - I_{t-1}(x,y)|

If a region changes significantly over time, it appears bright in the difference mask. This is computationally light and reacts quickly to movement, but it is sensitive to noise and small camera/illumination variations.

Background subtraction (MOG2) models the scene background and classifies each pixel as background or foreground over time. It is better at separating persistent static structure (buildings, road markings) from moving objects. However, it may produce ghost artifacts when lighting changes abruptly or when objects pause for long periods.

In this notebook, both techniques are fused by combining their binary masks. This reduces missed detections: frame differencing captures immediate temporal changes, while background subtraction provides scene-level foreground modeling. Before segmentation, Gaussian blur suppresses high-frequency noise; after segmentation, morphological open/close operations reduce isolated blobs and fill small holes.

Strengths, weaknesses, and failure scenarios
Strengths include low computational cost, interpretable processing stages, and easy adaptation to fixed-camera traffic scenes. ROI restriction and contour-size filtering significantly reduce non-vehicle detections. Centroid-based tracking helps avoid duplicate counts by ensuring each vehicle is counted once.

Weaknesses remain: the tracker is a nearest-neighbour association model, so identity switches can occur in dense congestion or heavy occlusion. A single global threshold may underperform under strong weather or illumination shifts. Perspective variation can also change apparent vehicle size, which affects contour filtering.

Failure scenarios include overlapping vehicles, abrupt shadows, reflections, and temporary stop-and-go patterns near the counting line. These conditions can split or merge blobs and cause under- or over-counting. The current implementation mitigates these effects but cannot fully remove them in all cases.

Alternative state-of-the-art approach
A stronger alternative is detector-based tracking (for example, YOLO + ByteTrack/DeepSORT). A deep detector can classify cars more robustly under variable lighting and complex backgrounds, while modern trackers maintain identity through partial occlusion. This approach usually improves counting accuracy, especially in crowded scenes, but it requires more computation, model files, and parameter tuning. For this assignment, the current classical approach is appropriate because it is lightweight, transparent, and directly aligned with the required frame-differencing and background-subtraction methods.

1) Brief explanation of the application
The notebook implements a lossless .ex2 codec using Rice coding. Each WAV is read as PCM samples, converted to signed integers, and transformed into first-order residuals (r_t = s_t - s_(t-1), with r_0 = s_0). Residual coding is important because audio samples are often correlated; differences are usually smaller than raw amplitudes. Residuals are zigzag-mapped to non-negative integers and then Rice-coded using parameter K.

For each mapped value u, Rice coding splits it into:
- quotient: q = floor(u / 2^K)
- remainder: r = u mod 2^K

The quotient is unary coded (a run of 1s followed by 0), and the remainder is stored in exactly K bits. The decoder reverses all steps (Rice decode -> zigzag inverse -> cumulative sum) to reconstruct the exact original PCM signal.

2) Correctness and lossless verification
The implementation includes a small-integer sanity test to validate unary quotient coding, remainder packing, and signed-sample handling before running WAV files. After compression, each .ex2 is decoded into a WAV and checked using:

np.array_equal(original, decoded)

Additionally, decoded raw PCM bytes are compared with the original bytes. In this run, all checks passed for both files and both K values, so the codec is lossless.

3) Why Sound1 and Sound2 differ so much in compression
The difference is caused by source statistics. Rice coding is very effective when many values are near zero (small residual magnitudes), because unary quotients stay short. Sound1.wav appears to have smoother local sample changes, so K=4 gives a real size reduction (14.43%). In contrast, Sound2.wav likely contains more abrupt changes, richer transients, or wider dynamic spread, producing large residual magnitudes. Large values create long unary prefixes and dramatically increase coded size. This explains why Sound2.wav expands heavily rather than compressing.

4) Effect of K on performance
K controls the tradeoff between quotient length and fixed remainder bits. Lower K (e.g., 2) reduces remainder bits but increases quotient lengths, which can hurt performance when values are not very small. Higher K (e.g., 4) shortens quotients at the cost of more remainder bits. In this experiment, K=4 is consistently better than K=2 for both files, showing that the underlying value distribution favors a larger remainder budget.

5) Improvements
Compression can be improved using block-adaptive K selection, higher-order prediction, or channel-wise decorrelation for multi-channel content. These methods reduce residual entropy before Rice coding and usually improve robustness across diverse audio types while keeping lossless reconstruction.

Brief analysis of the application
This application automates the technical compliance workflow for festival submissions. It performs three connected tasks: metadata examination, non-compliance reporting, and enforced conversion. First, every file in the input folder is inspected with `ffprobe` and parsed into explicit technical fields. Second, each field is compared against the required specification (container, video/audio codecs, frame rate, aspect ratio, resolution, video bitrate range, audio bitrate limit, and stereo channels). The notebook then writes a TXT report that identifies each non-compliant title and lists the exact problematic fields. Third, every non-compliant file is converted to a new copy whose filename ends in `_formatOK.mp4`, then re-checked with `ffprobe` to confirm that conversion succeeded.

This design avoids manual inspection and enforces repeatable decisions. It is robust for batches because the same rule set is applied consistently to all videos. It also preserves traceability: both pre-conversion failures and post-conversion status are explicit, so reviewers can verify the pipeline outcomes quickly.

Technical terms (required)
- Container (format): The outer file wrapper (e.g., MP4) that holds encoded streams and metadata.
- Video codec: Algorithm used to compress/decompress the video stream (required: H.264 / `h264`).
- Audio codec: Algorithm used for audio compression/decompression (required: AAC / `aac`).
- Frame rate (fps): Number of video frames displayed per second (required: 25 fps).
- Aspect ratio: Proportional relationship between width and height (required: 16:9).
- Resolution: Pixel dimensions of each frame (required: 640 x 360).
- Video bitrate: Bits per second assigned to video stream quality (required range: 2-5 Mb/s).
- Audio bitrate: Bits per second for audio stream quality (required: up to 256 kb/s).
- Audio channels: Number of independent audio channels (required: stereo, i.e., 2 channels).

Why this approach is effective and how to enhance it
The strongest part of this solution is deterministic checking with explicit thresholds. Instead of relying on defaults, conversion parameters are fully specified (`libx264`, `aac`, 25 fps, 640x360, bitrate constraints, stereo), which directly aligns with the assignment tips. Post-conversion validation closes the loop and ensures outputs truly satisfy requirements.

Potential improvements include: adding tolerance windows configurable per festival edition, exporting report data to CSV/JSON in addition to TXT, and including visual quality checks (e.g., VMAF/PSNR) when strict bitrate constraints are required across diverse source materials. Nonetheless, for this coursework scope, the implemented pipeline is complete, automated, and aligned with all specified technical constraints.

Exercise 4 Report 
Emerging Computer Vision and Audio Processing for Retail / E-Commerce

Introduction
Retail and e-commerce are moving from simple automation to intelligent, multimodal systems. In practice, this means using computer vision and audio together to understand customer behavior, monitor stock, improve search, and reduce losses. In this report, I critically discuss three emerging applications, then explain two key technical methods in more depth, and finally propose two creative real-world uses that could solve practical problems.

1) Critical discussion of three emerging applications

Application 1: Frictionless checkout
What is it?
Frictionless checkout is a system where customers pick items and leave, while cameras/sensors identify products and automatically generate payment.

What technique does it use?
It usually combines object detection, multi-object tracking, person re-identification, and event recognition (for example detecting “pick-up” and “put-back” actions). Audio can support edge cases, such as detecting scan sounds or dispute interactions.

Why is it effective?
It removes queues, reduces abandoned purchases caused by waiting, and improves store throughput. It also gives useful operational data (peak times, congestion zones, and product interaction patterns).

What are limitations?
Accuracy drops in crowded scenes with occlusion. Similar-looking products can confuse vision models. There are also privacy and fairness concerns if systems are not audited properly. Finally, deployment cost is high because stores need camera infrastructure, calibration, and maintenance.

How can it be improved?
A practical improvement is multimodal fusion: combine camera data with shelf-weight sensors and audio events to reduce ambiguity. Another is uncertainty-aware decision logic that sends low-confidence cases to a human reviewer instead of forcing automatic decisions.

Application 2: Intelligent shelf monitoring
What is it?
This system checks shelves continuously to detect out-of-stock products, wrong product placement, and planogram violations.

What technique does it use?
It relies on object detection/segmentation and OCR for labels/price tags, plus temporal smoothing to avoid false alarms from brief occlusions.

Why is it effective?
It reduces missed sales caused by stock-outs and improves merchandising consistency. It can also help warehouse picking quality by visually verifying bins/shelves.

What are limitations?
It is sensitive to domain shift: lighting changes, camera angle changes, reflective packaging, and seasonal redesigns can all reduce model performance. Small items and partial visibility remain difficult.

How can it be improved?
Use continual learning with drift detection, and active learning to label only the hardest cases. Also, cross-check vision alerts with other signals (RFID, inventory logs, or shelf sensors) before triggering replenishment.

Application 3: Multimodal product search and assistance
What is it?
Users search with mixed inputs such as image + text + voice (e.g., “find this bag in black below £60”).

What technique does it use?
Vision-language (and optionally audio) embeddings map different modalities into one shared feature space, then retrieval/reranking selects candidate products.

Why is it effective?
It helps users who cannot describe a product well in text and improves discovery in mobile shopping contexts. This can increase conversion and customer satisfaction.

What are limitations?
Speech ambiguity, accents, background noise, and dataset bias can hurt results. Retrieval may over-focus on visual similarity and ignore stock/policy constraints.

How can it be improved?
Add constrained reranking using inventory, size, policy, and price filters. Also provide explainable reasons for matches (“matched by shape, texture, and color”).

2) Technical discussion of two key techniques

Technique A: Transformer-based detection and tracking for retail video
Pipeline (simplified):
Camera frames -> CNN/ViT backbone -> transformer encoder/decoder -> object boxes/classes -> tracker -> business events.

Key equation (self-attention):
Attention(Q,K,V) = softmax((QK^T)/sqrt(d_k))V

Why it matters:
Compared with older local detectors, transformer-based approaches model wider context, which is useful in cluttered aisles and busy checkout scenes. With tracking-by-detection, the system can convert frame-level detections into event-level outputs (pick/return/counting/queue analytics).

Main strengths:
- strong contextual reasoning
- scalable architecture for complex scenes
- compatible with end-to-end learning

Main weaknesses:
- high compute and data requirements
- identity switching can still happen with severe occlusion

Technique B: Cross-modal contrastive embeddings (CLIP-style, plus audio branch)
Pipeline (simplified):
Image encoder + text encoder + audio encoder -> projection layers -> shared embedding space -> nearest-neighbor retrieval/reranking.

Core objective (InfoNCE style):
L = -log( exp(sim(z_i,z_t)/tau) / sum_j exp(sim(z_i,z_tj)/tau) )

Why it matters:
This method enables practical multimodal search in e-commerce catalogs. If metadata is poor, learned embeddings still capture visual and semantic similarity. Audio can add user intent from spoken queries.

Main strengths:
- flexible interaction (voice/text/image)
- good scalability for large catalogs

Main weaknesses:
- sensitive to biased or noisy training data
- requires policy-aware reranking after retrieval

3) Two creative / novel uses

Novel use 1: Return-fraud triage using video + acoustic cues
In returns processing, combine visual inspection (item condition/identity) with acoustic signatures (package opening, object impact, shake patterns). A multimodal anomaly detector can flag suspicious returns for manual verification. This could reduce both fraudulent refunds and false accusations against honest customers.

Novel use 2: Accessibility-first in-store assistant
A mobile/wearable assistant can detect products on shelves and provide short adaptive audio prompts (price, allergens, offers, alternatives). It can also listen for user intent and environmental warnings (crowding, announcements). This directly supports inclusive retail for visually impaired and neurodivergent shoppers.

Conclusion
The most important lesson is that high-performing retail intelligence is rarely single-modality. Vision gives spatial understanding, while audio adds context that cameras often miss. However, technical performance alone is not enough: reliability under shift, fairness, privacy, and explainability are essential for real deployment. The two techniques discussed (transformer-based scene understanding and contrastive multimodal embeddings) are powerful, but they should be combined with uncertainty handling, human oversight, and policy constraints. With these safeguards, multimodal systems can solve real problems in retail/e-commerce while remaining practical and trustworthy.
